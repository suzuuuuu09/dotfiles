# 指定された変更だけを公開する

1. 許可された操作、対象コミットまたはファイル、PRのベース、push先のリモートとrefを特定する。現在のブランチ、追跡設定、worktree、ステージ済み・未ステージ・未追跡の変更を確認する。`git ls-remote` などでリモート側の関連refを照合し、宛先を判断できなければ確認する。
2. 新規の変更を専用ブランチで届ける場合は、編集前に作業先を用意する。修正が既に混在するブランチにある場合は、確認したベースから別worktreeを作り、対象コミットか変更箇所だけを移す。元の作業ツリーと履歴を保全する。コミット内に対象外の差分や暗黙の依存があれば、対象変更を分離できるまで公開を保留する。
3. 公開直前に宛先とベースのrefを再確認する。pushでは宛先に含まれる対象コミットと、今回送るコミットを分けて確認する。追跡ブランチのahead表示はその追跡先との比較として扱い、古いローカルのリモート追跡refと実際の宛先refも区別する。引数なしのpush先は追跡先だけで決まらないため、関連設定が分からない場合は未確定とする。調査のみの回答にも、今の照合結果と、次回の公開直前にどの宛先refを再確認するかを記す。PRでは候補ブランチのコミット一覧と、ベースとの共通祖先からの差分を両方確認する。対象ファイル、確認結果、PRを作る場合は本文を示す。宛先が動いて範囲が変わった場合は照合し直す。
4. 許可された操作の後にリモートrefと、該当する場合はPRのベース・ヘッドを確認する。新たに送ったコミット、宛先に既にあった関連コミット、PRの範囲を報告する。保護や競合で止まった場合は、対象を絞った別ブランチなど、元の作業を保全できる経路を確認する。
