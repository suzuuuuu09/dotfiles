# エージェントの指示とSkillを監査する

1. 対象のクライアント、作業ディレクトリ、確認期間を特定する。全体・ユーザー・リポジトリの指示ファイル、設定の優先順位、実際に読み込まれるSkillの配置を確認する。シンボリックリンクと管理情報をたどり、配布元と現在の配置を照合する。採取済みの記録を根拠とする依頼では、その記録を使い、足りない事実は未確認と記す。
2. 使用実績を問われたら、ユーザーの明示呼び出し、別のSkillからの参照、クライアントの記録で確認できた自動発動を数える。ツール呼び出しと結果を対応づけ、通常の依頼に続くファイル読み取りだけなら「発動経路不明」とする。監査中の読み取り、履歴の引用、別エージェントの作業は、対象セッションの発動実績の集計から除く。ログの欠落や期間も記録する。
3. 重複は候補の説明だけで決めず、発動条件、本文の手順、出力、参照先を照合する。選択を変える案では、残すSkillからの依存を再帰的にたどり、対象クライアントで参照先が解決できるか確認する。使用頻度の低さだけなら維持し、誤発動、指示の衝突、依存切れなど、確認できた問題に対して変更を提案する。
4. 問題ごとに有効な設定、根拠、最小の変更案、影響する作業手順を示す。明示呼び出しを残す案では、導入済みの版で暗黙発動だけを止められるか確認する。編集も依頼された場合は管理元で変更し、静的な設定確認、選択結果の評価、実環境への反映をそれぞれ実施した範囲で報告する。
